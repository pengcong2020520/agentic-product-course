# 章节写法

一句话原则：**先让读者感到问题，再给出一个机制；正文讲道理，细节折叠，代码逐步展开。**

参考样本：learn-claude-code 的 `s01_agent_loop/README.zh.md`（简单章）与 `s09_memory/README.zh.md`（复杂章）。

## 章节 README 模板（每章一样，`tests/test_chapter_readmes.py` 强制）

```markdown
# sNN: 名称 — 一句话说明这一章让产品获得什么

s01 → ... → `sNN` → [sNN+1](../sNN+1_名字/) → ... → s最后        ← 当前章反引号，下一章是链接

> *"一句格言"* — 一句话解释这一章的核心道理。
>
> **方法层**：这一章在两个数据集 / 中台 / 应用里补上了哪一块。      ← 层名按章选：方法层、中台层、应用层

---

## 问题
## 解决方案
## 工作原理
## 试一下
## 接下来
```

复杂章可以在"问题"与"工作原理"之间插入以主题命名的 `##` 小节（例如"全部写进 system prompt，为什么不合适"），但五个固定小节的顺序不变。

### 每节怎么写

- **问题**：从一个读者能想象的具体场景开始（"你从应用商店抓下来 5,522 条评论……"），用短段落写出不解决会怎样；最后一句点出这一章要做的事。不列参数，不写背景史。
- **解决方案**：一张图（`images/*.svg`）或一张小表说清机制（信号 | 含义 | 动作）；一两段话讲为什么这样做、为什么不用更直接的做法。
- **工作原理**：分"第 1 步、第 2 步……"展开，每步一句说明 + 一段**逐字出自本章 `code.py`** 的代码；最后组装成完整的函数或命令。数字只保留能帮助理解的（"少于 10 个字算信息量不足"）。
- **试一下**：先写准备（安装、`.env`），再给可直接复制的命令；列 2–3 个可以尝试的输入或参数；以"**观察重点**：……"收尾，告诉读者该盯住哪个现象。
- **接下来**：一两句写出本章留下的新缺口，再用一两个问题引出下一章（"s05 → 两个模型标得不一样时，听谁的？"）。

### 深入内容：折叠，不另开文件

参数全表、边界情况、完整命令对照、实现取舍，放进 `<details><summary>……</summary> … </details>`，想深入时再展开。不再使用 `docs/design.md`。

### 文风

- 第二人称"你"，短段落，一段只说一件事；
- 先现象后概念，先例子后定义；用真实数据举例（条数、比例），数字附出处；
- 表格用于对照（信号/含义/动作、做/不做），列表用于步骤；
- 专有名词、命令、文件名原样保留，用反引号。

### 不要写的东西（发现就改）

- 参数清单式的正文：一段里堆满参数名、阈值、环境变量（放进 `<details>`）；
- 项目改造史与新旧对比："原来/现在""本轮""改造""第 0 步"；
- 只有链接、没有过渡的"接下来"；
- 前文伏笔与后文实际设计矛盾；
- 评论原文：只用改写后的例子或统计数字。

## 根 README

依次是：一句话论点（本课："两个数据集定义一个产品"）→ 论点展开 → ASCII 模式图 → "N 个递进式课程，每课加一个机制，每个机制一句格言"的清单（`> **sNN** *"格言"* — 一句话`）→ 核心代码模式 → 学习路径（mermaid）→ 全部章节表（章节 | 主题 | 关键概念）→ 如何阅读 → 项目结构 → 学完之后。格言与一句话说明在根 README、章节 README 引用块、章节表里用同一套措辞。

## code.py 文档字符串

```python
#!/usr/bin/env python3
"""
sNN_名字 - 本章名

一行流程：输入 → 处理 → 输出（可配 ASCII 小图）

Usage:
    python sNN_名字/code.py <子命令> [参数]
"""
```

## 分析报告（数据报告、评测报告、产品定义）

同样的文风：先给结论（一句话 + 一张表），再给证据（条数、比例、样本 id），最后写局限与下一步。报告只含统计数字与改写后的例子，不含原文。
