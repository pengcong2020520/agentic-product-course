# 阶段回顾与全仓 review

## 一、阶段回顾（每完成一个阶段）

1. **本章自查**：关键能力在运行时是否真的生效（不是只有测试替身）；README（含折叠的深入内容）、课程的说法与代码一致。
2. **回看前面所有章节**：
   - 本章做的事，前文有没有预告过？预告的说法和实际一致吗？
   - 前文的边界说明（"本章不提供 X"）是否该补上"在 sNN 兑现"？
   - 开发本章时发现的问题，前面哪些阶段也有，需要回补？
3. 列清单，每条附证据（文件:行、命令输出）；先核实再列，排除不成立的项。
4. 拆成互不重叠的任务并行处理（按目录拆），负责人验证与合并。

## 二、全仓 review（全部完成后，或路线大改后）

### 1. 先抽骨架，一眼看出问题

用脚本把每章的标题、"对应问题"标注、"要回答的问题"第一段、"下一章"第一段排在一起看，检查：
- 标题、引言块、导航、六问标注的格式是否全书一致；
- 每章开头是否接上一章，结尾是否引出下一章；
- 问题框架总表与各章标注是否一一对应（写脚本对比）。

### 2. 逐项检查清单

**全书骨架**
- [ ] 根 README、导论、阶段总览、路线图、网站分组：阶段数、组名、一句话说明一致；没有"规划中""已完成"残留
- [ ] 导论的产品终态与结构图包含了全部阶段带来的能力
- [ ] 阶段总览"每阶段加了什么"逐章齐全、描述与该章一致

**章节写法**（对照 chapter-writing）
- [ ] 核心概念先讲道理，不是参数清单
- [ ] 没有项目改造史、"本轮/本期"等开发过程措辞
- [ ] 参数与细节折叠在 `<details>` 里，五个固定小节全书一致

**前后呼应**
- [ ] 伏笔都兑现了，没有被后文推翻
- [ ] 跨章引用（"进入 sNN""见 sNN"）指向正确
- [ ] 同一概念在各处叫法一致

**不该出现的东西**
- [ ] 教学目录里没有开发过程文档（计划稿、改造记录、过时方案）；用 `git grep` 查所有引用后再删
- [ ] 每章目录里的图与课程网站上的图同源、最新

**跑起来的内容**
- [ ] 网站各页（全景、长文、课时、术语、增量、工作台）与文档一致；截图看一遍（文字重叠、排版溢出）
- [ ] 部署到线上后亲眼确认新内容已生效

### 3. 修改与交付

- 骨架与关键章节正文由负责人亲自改；批量机械性修改（删文件修引用、精简长文、统一结构）写任务说明交给执行者，负责人审查；
- 改动多时先存一个检查点提交，执行者并行时确保改的文件不重叠；
- 完整跑一遍全部检查与测试，截图核对，PR 写清"为什么、改了什么、怎么验证"；
- 合并后检查 main 的 CI，部署并确认线上；
- 最后向课程负责人汇报：发现了什么问题（分类）、改了什么、还有什么没做。
