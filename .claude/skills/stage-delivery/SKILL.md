# 交付一个阶段

一个阶段走完下面全部步骤才算完成，再开下一个阶段。每一步的产出都要能被检查。

## 0. 设计稿（负责人写，课程负责人确认）

写一份 `sNN-design-draft.md`（放仓库外）：
- **要回答的问题**：上一章做到什么，这一章补什么缺口；
- **只加一个单元**：名称与职责；
- **已定决策**：一张表，"问题 | 决定 | 理由"，**关键数值全部写死**（超时、上限、阈值、默认值），按教程够用来定；
- **诚实的边界**：本章不解决什么、留给哪一章；
- **教学材料**：对应哪几个框架问题、离线实验 ≥3 个、机制动画 2 个、服务器验收步骤；
- **任务拆分**：谁做什么。

拿不准的取舍（技术选型、拆不拆章、真实环境怎么测）用选择题问课程负责人，给出推荐项。确认后才开工。

## 1. 开发

- 从上一阶段复制出新快照（新分支 + 独立 worktree），**只加这一个单元**。
- 按 delegate-and-review 写任务说明派给执行者，验收清单里列出：离线测试、真实依赖测试、部署测试各自的命令与预期。
- 复制后 grep 上一阶段编号，清掉残留命名（数据库名、项目名、目录名、端口）。

## 2. 审查与分层验证（负责人亲自做）

按 quality-gates 的三层依次通过：
1. 本机：`npm test`（离线）、真实数据库与 Redis 的集成测试；
2. 服务器临时环境：真实系统权限 / 真实外部服务的测试，放在临时目录，跑完清理；
3. 部署与真实演练：部署后用真实模型做小额度验收（先确认费用），把本章的关键行为亲眼走一遍（故障类章节要真的 kill / pause / 断网）。

再让另一个模型做只读交叉审查，结论逐条复核，成立的打回返工，返工后从第 1 层重新验证。

## 3. 全仓登记与课程

- 阶段总览、导论章节表、根 README 路线、路线图与架构图数据、增量页、CI 矩阵、统一测试入口；
- 上一章的"下一章"改为指向本章；本章导航条；所有章节导航条补上本章；
- 课程素材：机制课、长文章节、阶段演示、工作台卡片；**术语释义由负责人亲自写**；
- 本章 README 按 chapter-writing 检查一遍（深入内容折叠在 `<details>`）；
- 重新生成课程与图，`python -m pytest tests -q` 全部通过；验证记录只能来自真实环境的完整运行。

## 4. 合并与上线

- 一次只开一个 PR；PR 说明写清：这一章回答什么、新增单元、验证（三层各自结果）、一并修正的问题；
- CI 通过后 squash 合并；**合并后检查 main 的 CI**；
- 从干净的 main 部署；部署失败先看具体报错判断是不是外部原因（镜像源、磁盘），不影响线上就先恢复线上。

## 5. 阶段回顾

按 course-review 的"阶段回顾"做一遍：本章说法与代码是否一致；前面各章有没有因为本章而过时、伏笔是否兑现或被推翻。发现的问题列清单、附证据，拆成互不重叠的任务并行处理。

## 完成标准（逐条打勾）

- [ ] 设计稿已确认，数值写死
- [ ] 三层验证全部通过，交叉审查发现的问题已处理
- [ ] 全仓登记、课程素材、术语完成，完整检查通过
- [ ] PR 合并，main CI 通过，线上已部署并亲眼确认
- [ ] 阶段回顾完成，清单已处理或已记录
