## 2. 方法主线：证据驱动六步法

| 步 | 回答的问题 | 出口产物 | 关口 |
|---|---|---|---|
| ① 洞察 | 值不值得做？AI 适不适合？ | 机会判断卡 | 继续 / 补证据 / 停止 |
| ② 承诺 | 为谁做、做到什么算成功、什么绝不能做？ | 定位、MVP 范围、边界处置表、业务标准、**首批 Ground Truth** | 标准是否可度量 |
| ③ 设计 | AI 在什么状态下怎样行动？ | Use Case 包、能力规格、指标、PRD | 每个能力都有验收方式 |
| ④ 构建 | 能不能真的跑起来？ | 可运行版本 + 运行证据 | GT 能执行 |
| ⑤ 验证 | 做得够不够好、能不能放量？ | 评测报告与发布建议 | 通过 / 有条件通过 / 不通过 / 数据不足 |
| ⑥ 运营 | 上线后怎样越做越好？ | 观测、Bad Case、变更包 | 扩大 / 保持 / 回滚 |

相对常见做法的改进：
1. **评测前移**：Ground Truth 从第②步就开始写，第⑤步只是把它体系化，不是到最后才想"怎么评"。
2. **每步一个关口**：关口判定都有三种结果：通过、不通过、没能判定；没能判定不算通过。
3. **⑤⑥是一个循环**：线上 Bad Case 回到第③或第④步，而不是线性走完就结束。
4. **平台沉淀**：同一个需求在应用里反复出现，就沉淀为中台能力。这是贯穿全书"中台 × 应用"两条线的依据。

## 3. 两条线：通用中台 × 陪伴定制

每一项中台能力都分两层讲：**通用中台提供什么** → **陪伴产品要求它做什么定制**。

| 中台能力 | 通用中台 | 陪伴产品的定制 |
|---|---|---|
| 入口 | CLI、IM 机器人；入口与实现解耦 | 长期一对一会话；主动触达（勿扰、冷却、频控） |
| 运行底座 | Workspace 发布只读 + 用户目录隔离 | 每个"用户 × 角色"一份关系状态；版本升级不能丢关系 |
| 模型服务 | 统一接口、路由、配额、成本 | 长关系的上下文成本；按"有效关系续接"核算单位成本 |
| 知识 | 有来源、有版本、按需检索 | 角色母版、世界观、对话方法 |
| 记忆 | 写入、召回、查看、删除 | 用户 / 角色 / 关系三类记忆；共同经历；纠正后立即生效；低置信不编造 |
| Skill / 工具 | Skill 目录、MCP 网关 | 设置引导、回复编排、角色生活、主动关怀 |
| 定时任务 | 触发、幂等、可取消 | "知道何时不行动"：没有真实由头就零发送 |
| 语音 | 识别、合成服务 | 角色专属音色，音色是角色资产的一部分 |
| 身份与权限 | 可信身份、RBAC | 关系数据只属于本人；角色运营方看不到私聊原文 |
| 评测 | GT、执行引擎、评分、报告 | 人设一致、记忆忠实、关系连续等主观维度：LLM Judge + 人工校准；模拟用户长期多轮 |
| 可观测 | Trace、指标、反馈 | 关系续接率、隐式不满（纠正、冷淡、流失）信号 |
| 发布 | 发布快照、灰度、回滚 | 按用户稳定分组；旧关系状态兼容迁移 |
