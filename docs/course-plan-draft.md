# 课程规划草案（待讨论，非定稿）

依据：[`research/methodology.md`](research/methodology.md)。

## 1. 定位

**一句话**：带读者亲手把一个 Agentic 产品从想法做到生产——先定义任务与边界、先建评测，再构建、加护栏、上线，最后用线上数据让它持续变好。

**学完以后**：读者亲手做出了 ___（示例产品，见第 3 节），它能在真实用户面前稳定完成任务、知道何时转人工、每次发布都有评测兜底，并能从线上失败中自动沉淀新的评测用例。

## 2. 问题框架（草案）：一个 Agentic 产品要回答的七个问题

| # | 问题 | 对应方法论 |
|---|---|---|
| ① | 这件事值得交给 Agent 吗？做到什么算成功？ | 选任务、Workflow vs Agent、成功标准 |
| ② | 怎么知道它做得好不好？ | 评测集、评分器、pass^k |
| ③ | 它看到什么、能用什么？ | 上下文工程、工具设计、知识 |
| ④ | 一个 Agent 还是一组？谁来编排？ | 工作流模式、多 Agent 取舍 |
| ⑤ | 什么时候必须停下来问人？什么绝不能做？ | 护栏、人工介入、安全 |
| ⑥ | 上线后发生了什么、花了多少？ | 可观测、成本与延迟 |
| ⑦ | 怎样越用越好？ | 错误分析、打标、数据飞轮、发布管理 |

## 3. 示例产品候选

| 候选 | 对应市场产品 | 适合教学的地方 | 难点 |
|---|---|---|---|
| **A. 电商客服 Agent（推荐）** | Sierra、Decagon、Intercom Fin | 有业务政策、工具（查订单/退款）、人工移交；可按最终数据库状态做确定性评分（τ-bench 思路）；pass^k 有意义；线上指标清晰（解决率、转人工率、每次解决成本）；数据闭环自然 | 多 Agent 场景要设计（如路由 + 售后专员 + 质检） |
| B. 深度研究 Agent | OpenAI/Gemini Deep Research、Manus | 多 Agent 并行最自然；引用核对 | 评测偏主观、依赖联网搜索（成本与稳定性） |
| C. 编码 Agent | Cursor、Claude Code、Devin | 市场最大；测试即评测 | 产品本身极复杂，读者难以从零做出可比的东西 |

推荐 A，并在"多 Agent"一章用 B 的模式（并行调研子任务）作为对比案例。

## 4. 路线草案（每阶段只加一个单元）

| 组 | 阶段 | 新增的一个单元 | 问题 |
|---|---|---|---|
| 一、定义 | s00 | 任务与边界：产品说明、能力边界、成功标准；先用最简单的 Workflow 跑通 | ① |
| | s01 | 最小 Agent：一个循环 + 三个工具，自己掌控上下文与状态 | ③ |
| 二、先能评 | s02 | 评测集与确定性评分：用例、参考解、按状态评分 | ② |
| | s03 | 模型评判与人工校准：rubric、两两比较、TPR/TNR、三态判定 | ② |
| | s04 | 稳定性与回归：多次运行、pass^k、能力评测与回归评测、CI 里跑评测 | ② |
| 三、做好它 | s05 | 上下文与工具工程：工具描述、错误压缩、知识检索 | ③ |
| | s06 | 用户仿真：LLM 模拟用户 + 多轮评测 | ② |
| | s07 | 编排与多 Agent：路由、移交、并行子任务；何时不该拆 | ④ |
| 四、守得住 | s08 | 护栏与人工介入：工具风险分级、审批、失败阈值转人工 | ⑤ |
| | s09 | 安全与对抗测试：提示注入、越权、致命三要素的结构隔离 | ⑤ |
| 五、上线 | s10 | 可观测：trace、成本与延迟 | ⑥ |
| | s11 | 发布：上线清单、影子流量、灰度与回滚、版本管理 | ⑥ |
| 六、越用越好 | s12 | 错误分析与打标：开放编码 → 失败模式 → 标注规范与一致性 | ⑦ |
| | s13 | 数据飞轮：线上失败 → 新评测用例 → 改进 → 回归 → 再发布 | ⑦ |

## 5. 待确认

1. 示例产品：A / B / C 或其他。
2. 技术栈：语言（TypeScript / Python）、Agent 底座（直接调模型 API 自写循环 / Claude Agent SDK / OpenAI Agents SDK / 其他）、模型供应商。研究结论倾向"自己掌控循环"，便于讲清原理。
3. 前置要求：读者需要会什么？
4. 部署形态：本地 + 一键云部署，还是要求真实云端。
5. 路线顺序与粒度：14 章是否合适，哪些可合并或拆分。
