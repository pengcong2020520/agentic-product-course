# 课程规划草案 v7（待讨论，非定稿）

## 1. 产品哲学：Eval 驱动的 AI 产品方法论

> **两个数据集定义一个产品。**
> - **原始数据集定义"做什么"**：把用户声音和真实数据收集起来，按多个维度打标；标签的分布告诉我们为谁做、解决什么、做到哪里为止。
> - **评测集定义"做得多好"**：一整套对输入和输出的评估——输入是什么、期望怎样、怎么判定。产品的质量就是它在评测集上的表现。

由此得到全书的工作方式：

```text
 原始数据集 ──打标──▶ 产品定义 ──抽样与扩展──▶ 评测集 ──▶ 构建（让用例逐个通过）
      ▲                                                    │
      └──────── 线上数据回流（反馈、Trace、Bad Case）◀── 发布与运营
```

四条原则：
1. **产品定义可追溯**：定位、Use Case、边界、指标中的每一条，都能指回原始数据里的样本与标签，不凭感觉拍板。
2. **评测集先于代码**：先用评测集跑一遍裸模型，得到基线；之后每一章的构建都以"让哪些用例通过"为目标。
3. **质量只认评测集**：评测集覆盖输入、期望输出与判定；判定看回复、轨迹、状态、副作用四层；结果分通过、不通过、没能判定三态，没能判定不算通过。
4. **两个数据集一起生长**：线上数据回到原始数据集重新打标；新发现的问题扩充评测集；评测集不变，结论就不能变。

## 3. 两条线：通用中台 × 陪伴定制

每一项中台能力都分两层讲：**通用中台提供什么** → **陪伴产品要求它做什么定制**。

| 中台能力 | 通用中台 | 陪伴产品的定制 |
|---|---|---|
| 数据 | 原始数据采集、打标、数据集版本 | 情绪、关系阶段、陪伴需求等陪伴专属标签 |
| 评测 | GT、执行引擎、评分、报告 | 人设一致、记忆忠实、关系连续等主观维度；模拟用户长期多轮 |
| 入口 | CLI、IM 机器人；入口与实现解耦 | 长期一对一会话；主动触达（勿扰、冷却、频控） |
| 运行底座 | Workspace 发布只读 + 用户目录隔离 | 每个"用户 × 角色"一份关系状态；升级不能丢关系 |
| 模型服务 | 统一接口、路由、配额、成本 | 长关系的上下文成本；按"有效关系续接"核算单位成本 |
| 知识 | 有来源、有版本、按需检索 | 角色母版、世界观、对话方法 |
| 记忆 | 写入、召回、查看、删除 | 用户 / 角色 / 关系三类记忆；纠正后立即生效；低置信不编造 |
| Skill / 工具 | Skill 目录、MCP 网关 | 设置引导、回复编排、角色生活、主动关怀 |
| 定时任务 | 触发、幂等、可取消 | 没有真实由头就零发送 |
| 语音 | 识别、合成服务 | 角色专属音色，音色是角色资产 |
| 身份与权限 | 可信身份、RBAC | 关系数据只属于本人 |
| 可观测 | Trace、指标、反馈 | 关系续接率；纠正、冷淡、流失等隐式信号 |
| 发布 | 发布快照、灰度、回滚 | 按用户稳定分组；旧关系状态兼容迁移 |
