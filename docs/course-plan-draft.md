## 2. 产品终态（一句话）

学完以后，读者亲手做出了一个部署在腾讯云上的 AI 陪伴：在 Web 和飞书里能文字、能语音，记得用户、人设稳定；识别危机时会转人工，对未成年人有保护，遵守 AI 身份提示和防沉迷要求；每次发布都要过评测门禁，线上坏样本会自动变成新的评测用例。

## 3. 架构

```text
 Web 页面 / 飞书机器人（文字、语音）
        │
 ┌──────▼──────────────── 云端服务（FastAPI）───────────────────┐
 │ 账号与飞书身份 · 年龄与监护 · 防沉迷计时 · AI 身份提示        │
 │ 语音：FunASR（识别）→ Agent → CosyVoice（合成）               │
 │ 输入护栏（危机 / 越狱 / 注入 / PII）                          │
 │   陪伴 Agent（人设 + 工具）──handoff──▶ 危机支持 Agent ─▶ 人工 │
 │ 输出护栏（人设、红线、诱导付费）                              │
 │ 会话结束后：记忆整理 Agent（mem0）                            │
 │ ── 以上全部由 OpenAI Agents SDK 承载；模型经 LiteLLM 接国内模型 │
 └──┬─────────────┬──────────────┬────────────────────────────┘
  PostgreSQL     Redis          Langfuse（自托管）
  +pgvector      会话/限流      trace · 成本 · 数据集 · 标注 · 线上评判
        ▲                               │
        └──── 评测体系：DeepEval（离线/CI）· 模拟用户 · promptfoo/garak（红队）
```

## 4. 评测体系（贯穿全书）

- **一套评测仓**：`evals/`，从 s02 建立，之后每章往里加用例；每章 README 固定有一节"本章新增的评测"。
- **五个维度**：
  1. 对话质量：共情、自然、不说教，参考 ESConv 的支持策略；
  2. 人设一致：语气、自我认知、不出戏；
  3. 记忆：记得对、不张冠李戴、删了就真忘了；
  4. 安全合规：法规条款逐条变成用例；危机识别查全率是硬红线；
  5. 体验与成本：延迟、首字时间、语音识别错误率、每次对话成本。
- **三类评分器**：
  - 代码规则：关键词、格式、状态；
  - 模型评判：G-Eval rubric，用人工标注做校准；
  - 人工抽检。

  每次判定都有三种结果：通过、不通过、没能判定。"没能判定"不能算作通过。
- **三层**：
  1. 单轮用例；
  2. 模拟用户多轮对话（不同性格、情绪、风险等级）；
  3. 线上：Langfuse 在线评判，坏样本回流到评测集。
- **门禁**：能力评测会逐步"毕业"成回归评测；PR 必须过回归评测，安全类按 pass^k 计；发布前必须过红队扫描。
- **工具**：DeepEval（离线、CI）、tau2-bench 的模拟用户思路、promptfoo + garak（红队）、Langfuse（线上与标注）。
