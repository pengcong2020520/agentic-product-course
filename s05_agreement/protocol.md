# 标注与裁决规则（配合基因图谱 v0.2.1）

## 1. 角色

| 角色 | 谁 | 做什么 |
|---|---|---|
| 主标注 | Codex CLI（本机已登录） | 全量 4,557 条：双标样本 460 条 + 其余 4,097 条（`data/full`） |
| 独立复标 | Grok CLI（本机已登录） | 双标样本 460 条独立标注，**看不到**主标注结果 |
| 裁决 | 人（Argilla） | 处理分歧、红线基因与抽检 |

两个模型来自不同厂商，用来减少同源偏差。复标者只拿到规范与原文。Kimi 不参与标注，只作为课程中读者使用的轻量模型；`prelabel.py`（OpenAI 兼容接口预标）保留为备用。

## 2. 双标样本

- `s04_labeling/code.py sample` 按"应用 × 评分档（低 1–2 / 中 3 / 高 4–5）"分层，每层随机抽 10%，固定随机种子 42；切成每块 50 条。
- 样本独立于主标注结果抽取，不能按"模型没把握的"挑选。

## 3. 复标者必须遵守

1. 逐条阅读原文后自己判断，**不得写脚本调用模型，不得用关键词规则批量打标**。
2. 只按 `s03_product_genome/genome.md` 与 `s03_product_genome/genome.json` 的取值标注；看不出来选 `unknown`/`none`，不猜。
3. 输出 JSONL，每行一个对象，字段与 `prelabel.py` 输出的 `labels` 完全一致，另加 `id`。
4. 只写自己的输出目录 `data/double/<标注者>/`，不改任何其他文件。

## 4. 一致性计算（`s05_agreement/code.py agree`）

| 基因类型 | 指标 |
|---|---|
| 单选（G0、G4、G8、G9、G10、G15、G16） | Cohen's κ（有三方时另算 Fleiss' κ） |
| 多选（G1–G3、G5、G6、G7、G11、G12、G14、G17） | 逐标签二值化后的平均 κ；逐条 Jaccard |
| 强度（G8 强度） | 加权 κ（相差 1 档算半一致） |
| 文本（G13） | 不算 κ；只比"是否写了 Agent 应当"，再人工抽查 |

判定：κ ≥ 0.6 合格；0.4–0.6 要修订该基因的定义；< 0.4 说明定义不可操作，必须重写。**某一方输出缺失或格式不合法，记为"没能判定"，不计入一致，也不计入不一致，单独报告数量。**

## 5. 合并与裁决

1. **最终标注以主标注为准**：全量（含双标样本）的最终标注都取 Codex 的结果，保证全量口径一致；Grok 的复标只用于度量一致性、发现分歧。
2. **只裁决关键基因的分歧**（Argilla 中以 `needs_review` 标出），双标样本里 Codex 与 Grok：
   - G0 相关性不一致；
   - G5 一级触点**完全没有交集**（主次不同但有交集算部分一致）；
   - G15 可解性落在两个不同的具体层（一方"多层共同"、一方某一层算部分一致）；
   - G16 严重度不一致（严重度决定优先级，任何不一致都裁决）。

   裁决结果覆盖 Codex 的值，并保留双方原始标注。按此规则，460 条中 89 条（19%）进入裁决。
3. **"Agent 应当"不在这里审**：写了"Agent 应当"的样本会进入评测集，统一在构建评测集时（第二部分）逐条人工确认，避免重复审。
4. **一致性不合格的基因**：先改规范（升版本号），再让主标注者只重标该基因，重标后重新计算一致性。

## 6. 全量的质量结论

- 双标样本的一致性代表主标注（Codex）的可信度：某基因 κ 合格，则该基因的全量主标注可直接用于统计；不合格的基因只能在人工复核后使用。
- 报告必须写明：样本量、各基因 κ、没能判定的数量、裁决改动的比例。
